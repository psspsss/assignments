Block Interleaving Concept

Why We Need Interleaving

Block interleaving is a technique that reorders bits to improve error resilience in wireless channels. For 5G NR PBCH, it's applied after polar encoding and before rate matching.

Purpose: Burst errors in wireless channels (caused by fading, interference) can corrupt consecutive bits. Interleaving spreads these burst errors across the codeword, making them appear as independent errors that the decoder can correct more effectively.

Implementation: Block interleaving uses a matrix structure. Bits are written into the matrix row-by-row (left to right, top to bottom), then read out column-by-column (top to bottom, left to right). This simple permutation effectively disperses burst errors.

Interleaving Algorithm

Mathematical Definition

Matrix Dimensions

For a sequence of N bits, we define a matrix with R rows and C columns where:

// ─── Matrix Size Calculation ───
N = Total number of bits
R = Number of rows (interleaver depth)
C = Number of columns

Constraint: R × C ≥ N

// For PBCH (typical parameters):
N = 864 bits
R = 32 rows
C = ceil(N / R) = ceil(864 / 32) = 27 columns
Matrix size = 32 × 27 = 864 positions

Interleaving Process

1
Initialize Matrix
Create an R×C matrix (initially empty or with null values)
2
Write by Rows
Write input bits sequentially into matrix: left-to-right, top-to-bottom (row-major order)
3
Read by Columns
Read output bits sequentially from matrix: top-to-bottom, left-to-right (column-major order)

Mathematical Formulation

// ─── Input Sequence ───
d[n] for n = 0, 1, 2, ..., N-1

// ─── Write to Matrix (Row-Major) ───
for n = 0 to N-1:
  row = floor(n / C)
  col = n mod C
  matrix[row][col] = d[n]

// ─── Read from Matrix (Column-Major) ───
m = 0
for col = 0 to C-1:
  for row = 0 to R-1:
    if matrix[row][col] is valid:
      y[m] = matrix[row][col]
      m = m + 1

// ─── Permutation Formula ───
Input position: n
Output position: π(n) = (n mod C) × R + floor(n / C)
Interleaving Depth: The parameter R controls the interleaving depth. Larger R spreads bits further apart, providing better protection against longer burst errors, but requires more memory.

Performance Analysis

Benefits and Trade-offs

Burst Error Protection

Block interleaving with R rows can disperse burst errors up to length R into R independent single-bit errors (in ideal conditions).

// ─── Burst Error Analysis ───
R = Number of rows (interleaving depth)
Burst length ≤ R → Completely dispersed
Burst length > R → Partially dispersed

// Example: R = 8
Burst of 4 consecutive errors → 4 errors separated by ≥8 positions
Burst of 10 consecutive errors → Some errors still adjacent

// ─── Practical PBCH Example ───
N = 864 bits, R = 32, C = 27
Protection: Up to 32 consecutive bit errors dispersed
Separation: Consecutive bits separated by 32 positions

Comparison: With vs Without Interleaving

Aspect Without Interleaving With Block Interleaving
Burst Error Impact Corrupts adjacent coded bits → Decoder struggles Disperses across codeword → Independent errors
Decoding Performance Poor for burst errors (common in wireless) Much better for typical channel conditions
Latency Minimal (no reordering) Added delay (wait for full block)
Memory None required R × C matrix storage needed
Complexity Zero (no processing) Low (simple permutation)
Overall Vulnerable to real-world channels Essential for reliable communication

Matrix Width (C)
Flexible

Implementation
Efficient

Key Takeaways

✓ Essential Protection:
  • Block interleaving is critical for wireless channels
  • Transforms burst errors into dispersed errors
  • Significantly improves decoder performance

✓ Simple Yet Effective:
  • Matrix-based approach is easy to implement
  • Write by rows, read by columns
  • Deterministic permutation (reversible at receiver)

✓ Parameter Selection:
  • R determines burst protection capability
  • Typical PBCH uses R=32 for 864-bit codewords
  • Balance between protection and latency

✓ Standard Compliance:
  • Defined in 3GPP TS 38.212 Section 5.4.1.1
  • Applied to polar-coded channels (PBCH, PDCCH, PUCCH)
  • Part of the complete channel coding chain
