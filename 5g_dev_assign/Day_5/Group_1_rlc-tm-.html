Key Characteristics

TM Mode Overview

Transparent Mode (TM) provides the simplest RLC operation with no protocol overhead. Data passes through without modification.

Key Features:

  • No RLC Headers: TMD PDUs contain only the Data field
  • No Segmentation: RLC SDUs are not segmented
  • No ARQ: No retransmissions or acknowledgments
  • No Reordering: SDUs delivered as received
  • No Sequence Numbers: No SN field in PDUs

Supported Logical Channels:

  • BCCH (Broadcast Control Channel)
  • PCCH (Paging Control Channel)
  • CCCH (Common Control Channel)
  • SBCCH (Sidelink Broadcast Control Channel)

Use Cases:

  • System information broadcast
  • Paging messages
  • Initial access signaling
  • Scenarios where overhead must be minimal

Transmission Characteristics

Receive RLC SDU from upper layer via TM-RLC channel

2. No Processing

No segmentation: RLC SDUs are NOT segmented

No headers: No RLC headers are added

No sequence numbers: No SN assignment

3. Buffer Storage

4. Transmission

Submit complete, unmodified RLC SDU to lower layer (MAC) when notified

5. No Retransmission

TM mode has no ARQ mechanism - no retransmissions possible

Reception Characteristics

  • No Header Removal: TMD PDUs have no headers to remove
  • No Reassembly: SDUs are not segmented, so no reassembly needed
  • No Reordering: Delivered in received order
  • No Duplicate Detection: No mechanism to detect duplicates
  • No Error Detection: Relies entirely on lower layers

Reception Flow

1. PDU Reception

Receive TMD PDU from lower layer via logical channel

2. Direct Delivery

Immediately deliver to upper layer without any processing

TMD_PDU → Upper Layer (No modification)

3. No State Updates

TM mode has no state variables to update

4. No Timers

No timers are used in TM mode (no t-Reassembly, etc.)

5. Error Handling

All error detection and correction handled by physical/MAC layers

⚠️ Important Limitations

  • No reliability mechanism - lost packets are NOT recovered
  • No flow control or congestion management
  • Suitable only for broadcast/control channels where retransmission is not applicable

Key Differences from AM/UM Modes

TM Mode
  • No headers
  • No segmentation
  • No ARQ
  • No timers
  • No state variables
UM Mode
  • Has headers (SN, SI)
  • Segmentation supported
  • No ARQ
  • t-Reassembly timer
  • RX state variables
AM Mode
  • Full headers (SN, SI, P)
  • Segmentation/Re-segmentation
  • Full ARQ with STATUS
  • Multiple timers
  • TX & RX state variables
