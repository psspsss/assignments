Key Components

Architecture Overview

The RLC AM (Acknowledged Mode) entity consists of transmitting and receiving sides that work together to provide reliable data transfer with acknowledgments.

Components:

  • Transmission Buffer: Stores RLC SDUs with assigned sequence numbers
  • Retransmission Buffer: Holds AMD PDUs awaiting acknowledgment
  • Reception Buffer: Receives and stores AMD PDUs for reassembly
  • RLC Control: Manages STATUS PDUs and control signaling
  • Segmentation/Reassembly: Handles PDU fragmentation and reconstruction
  • Routing: Determines PDU delivery paths

📤 Transmit Operations (5.2.3.1)

Window & Operations

Transmission Priorities

The transmitting side follows strict prioritization:

  1. Highest Priority: RLC control PDUs (STATUS PDUs)
  2. Medium Priority: AMD PDUs with retransmissions (previously transmitted)
  3. Lower Priority: AMD PDUs with new data (not previously transmitted)

Process Steps

Step 1: Receive SDU from Upper Layer

When an RLC SDU is received:

SN = TX_Next Construct AMD PDU with SN = TX_Next TX_Next = TX_Next + 1

Step 2: Segmentation (if needed)

When submitting an AMD PDU containing a segment:

Set SN of AMD PDU = SN of corresponding RLC SDU Update segmentation info in header

Step 3: Positive Acknowledgment

When receiving STATUS PDU with ACK for SN = x:

Indicate successful delivery to upper layers TX_Next_Ack = SN of smallest unacknowledged RLC SDU where TX_Next_Ack ≤ SN ≤ TX_Next

Step 4: Discard (Optional - if configured)

If stopReTxDiscardedSDU is configured:

When upper layer requests discard of RLC SDU: Do NOT consider SDU or segments for TX/ReTX if already submitted to lower layers

Reception Process

Actions when AMD PDU Received (5.2.3.2.2)

When AMD PDU with byte segments y to z of SN = x is received:

IF x falls outside receiving window OR segments y to z already received: DISCARD received AMD PDU ELSE: PLACE in reception buffer IF some byte segments received before: DISCARD duplicate byte segments

Actions when Placed in Buffer (5.2.3.2.3)

When AMD PDU with SN = x is placed in reception buffer:

IF x ≥ RX_Next_Highest: RX_Next_Highest = x + 1 IF all bytes of RLC SDU with SN = x received: REASSEMBLE RLC SDU from AMD PDU(s) REMOVE RLC headers DELIVER to upper layer IF x == RX_Highest_Status: UPDATE RX_Highest_Status to first incomplete SDU IF x == RX_Next: UPDATE RX_Next to first incomplete SDU

Timer Management

t-Reassembly: Triggered when gaps are detected in received SNs

t-RxDiscard: (Optional) Discards old PDUs after timeout

🪟 Window Management

State Variables

Transmitter State Variables:

TX_Next - Next new SN to assign

TX_Next_Ack - Earliest unacknowledged SN

Receiver State Variables:

RX_Next - SN following last in-sequence completely received SDU

RX_Next_Highest - SN following highest received SN

RX_Highest_Status - Highest SN among not fully received SDUs

RX_Next_Status_Trigger - Trigger value for STATUS report

RX_Next_Discard_Trigger - Trigger for RX discard timer

Window Size

AM_Window_Size = 2^(SN field length - 1) For 12-bit SN: AM_Window_Size = 2048 For 18-bit SN: AM_Window_Size = 131072

The window ensures that sequence numbers don't wrap around while PDUs are still pending acknowledgment.

⏱️ Timers & Triggers

t-Reassembly Timer (5.2.3.2.4)

Detects missing AMD PDUs and triggers STATUS reporting.

Start Conditions:

START t-Reassembly when: (RX_Next_Highest > RX_Next + 1) OR (RX_Next_Highest == RX_Next + 1 AND missing byte segment exists for RX_Next) SET RX_Next_Status_Trigger = RX_Next_Highest

Stop Conditions:

STOP t-Reassembly when: (RX_Next_Status_Trigger == RX_Next) OR (RX_Next_Status_Trigger == RX_Next + 1 AND no missing segments for RX_Next) OR (RX_Next_Status_Trigger outside window AND RX_Next_Status_Trigger ≠ RX_Next + AM_Window_Size)

Expiry Actions:

WHEN t-Reassembly expires: UPDATE RX_Highest_Status to first incomplete SDU where SN ≥ RX_Next_Status_Trigger IF gaps still exist: RESTART t-Reassembly SET RX_Next_Status_Trigger = RX_Next_Highest
⏱️ Status: Idle
Duration: 0 ms
Trigger: -

t-RxDiscard Timer (5.2.3.2.5) [Optional]

Discards old AMD PDUs that have been buffered too long.

Configuration:

Only active if configured by upper layers. Helps prevent buffer overflow.

Expiry Actions:

WHEN t-RxDiscard expires: DISCARD AMD PDUs in reception buffer where: SN < RX_Next_Discard_Trigger UPDATE RX_Next to first incomplete SDU where: SN ≥ RX_Next_Discard_Trigger IF gaps still exist: RESTART t-RxDiscard SET RX_Next_Discard_Trigger = RX_Next_Highest

Key Points:

  • Only active if configured
  • Prevents buffer overflow
  • Works with t-Reassembly

🔄 Complete RLC AM Flow

End-to-End Data Transfer

This section demonstrates the complete flow of data through the RLC AM entity.

Phase 1: Data Arrival & Buffering

1. Upper layer delivers RLC SDU

2. TX entity assigns SN = TX_Next

3. AMD PDU created and stored in transmission buffer

4. TX_Next incremented

Phase 2: Segmentation (if needed)

1. Check if SDU size exceeds lower layer capacity

2. Segment RLC SDU into multiple AMD PDUs

3. Set appropriate segmentation info in headers

4. All segments share same SN

Phase 3: Transmission

1. Check transmitting window: TX_Next_Ack ≤ SN < TX_Next_Ack + AM_Window_Size

2. Priority: Control PDUs > Retransmissions > New data

3. Submit AMD PDU to lower layer

4. Store in retransmission buffer awaiting ACK

Phase 4: Reception

1. Receive AMD PDU from lower layer

2. Check if SN is within receiving window

3. Check for duplicates

4. Place in reception buffer (or discard if duplicate/outside window)

Phase 5: Reassembly

1. Check if all bytes of RLC SDU with SN = x are received

2. Reassemble RLC SDU from AMD PDU(s)

3. Remove RLC headers

4. Deliver complete RLC SDU to upper layer

5. Update RX_Next if this was in-sequence

Phase 6: Status Reporting

1. RX entity detects missing SNs

2. t-Reassembly timer triggers if gaps exist

3. Generate STATUS PDU with ACK/NACK info

4. Send STATUS PDU via RLC control block

Phase 7: Acknowledgment Processing

1. TX entity receives STATUS PDU

2. Process positive acknowledgments

3. Update TX_Next_Ack to smallest unacknowledged SN

4. Remove acknowledged PDUs from retransmission buffer

5. Notify upper layers of successful delivery

Phase 8: Retransmission (if NACK received)

1. Identify NACKed SNs from STATUS PDU

2. Retrieve AMD PDUs from retransmission buffer

3. Prioritize retransmission over new data

4. Retransmit AMD PDUs

5. Wait for next STATUS report
