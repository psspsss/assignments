RLC Acknowledged Mode (AM)

RLC AM provides reliable, in-order data delivery between DU and UE. It uses sequence numbering, acknowledgment feedback, and selective retransmission to guarantee that all PDUs reach the destination without corruption or loss.

• Layer: L2 (RLC sublayer)
• Standard: 3GPP TS 38.322
• Deployed at: DU (transmit) + UE (receive)
• Window Size: up to 4096 SNs (12-bit SN)
• Status Report: periodic + on-demand

ARQ Mechanism

Automatic Repeat reQuest (ARQ) is the error-control protocol at the heart of RLC AM. When the UE detects a missing sequence number in its receive buffer, it generates a Status PDU containing NACK entries for the missing SNs, triggering selective retransmission at the gNB.

• Type: Selective ARQ (not Go-Back-N)
• NACK triggers: gap detection + t-Reordering expiry
• Poll bit: requests immediate status report
• Max retransmissions: configurable (MAXRETX)
• t-PollRetransmit: ensures feedback arrives

Sequence Numbering

Each RLC PDU is assigned a unique Sequence Number (SN) before transmission. The transmit window slides as ACKs arrive. The receive window tracks the next expected SN (VR(R)) and detects gaps when out-of-order PDUs are received.

• TX variables: TX_Next, TX_Next_Ack
• RX variables: VR(R), VR(MR), VR(X), VR(H)
• SN size: 12-bit (4096 values) or 18-bit
• Window: SN_FieldLength defines range
• Wrap-around: handled by modular arithmetic

Retransmission Buffer Logic

The gNB maintains a retransmission buffer holding all unacknowledged PDUs. Upon receiving a NACK in a Status PDU, only the NACKed PDU(s) are retransmitted — this selective approach saves significant radio resources compared to Go-Back-N schemes.

• Buffer holds: all unACKed TX PDUs
• On NACK: selective resend of specific SN
• On ACK: PDU released from buffer
• Priority: retransmissions queued before new data
• RLC + HARQ: two-level ARQ mechanism
